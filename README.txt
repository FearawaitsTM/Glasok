ГЛАЗОК — OZON И WILDBERRIES + СЕРВЕР С ОБНОВЛЕНИЯМИ

API — БЫСТРЫЙ СТАРТ
1. На компьютере с сервером откройте «Глазок Сервер.exe».
2. В окне сервера введите Ozon Client-Id, Ozon Api-Key и/или токен WB.
3. Если клиенты на других ПК, включите доступ из локальной сети и
   перезапустите сервер кнопками «Остановить» и «Запустить».
4. На компьютере пользователя откройте «Глазок.exe» → «Подключение к
   серверу». Введите адрес и код из окна сервера.
5. Перейдите во вкладку Ozon или WB, отметьте любые нужные отчёты,
   задайте период в формате ГГГГ-ММ-ДД и нажмите «Получить выбранное».
6. В списке таблиц появятся «API — Объединённая сводка», исходные
   таблицы каждого отчёта и «API — Итоги».
7. Можно одновременно добавить ручные XLSX/CSV. Представление
   «Все источники вместе» показывает данные API и файлов рядом.

Ключи Ozon/WB хранятся на серверном ПК, на Windows защищены DPAPI и
клиентам не выдаются. Код подключения даёт доступ к данным отчётов —
передавайте его только своим пользователям. В локальной сети используется
HTTP; не открывайте порт 8765 напрямую в интернет. Для работы через
интернет потребуется отдельный защищённый канал или HTTPS-шлюз.
Пустые поля при сохранении ключей сохраняют прежние значения.
Если Ozon отвечает «HTTP 401 Invalid Api-Key», откройте «Глазок Сервер»,
введите заново ОБА поля Ozon (Client-Id и действующий Api-Key из одного
кабинета Seller API), затем нажмите «Сохранить». Не отправляйте ключи в чат.
Зелёное «сервер работает» подтверждает связь приложения с вашим сервером,
но не проверяет ключ Ozon. Финансы Ozon загружаются через актуальный метод
начислений по дням; за большой период загрузка может занять несколько минут.
Если WB отвечает «Остатки: HTTP 403» и «token does not satisfy additional
requirements», создайте или проверьте Персональный либо Сервисный токен WB
с категорией «Аналитика». Вставьте подходящий токен WB в окно «Глазок Сервер»
и сохраните. Связь с сервером при этом может оставаться рабочей: сервер
проверяется отдельно от прав токена Wildberries.
Доступность отчётов зависит от прав токена и тарифа кабинета.

ОБНОВЛЕНИЕ ПРИЛОЖЕНИЯ
В окне сервера нажмите «Выбрать и опубликовать Глазок.exe» и выберите
заранее собранный Windows EXE. Запущенные клиенты проверяют обновление
примерно раз в минуту, скачивают его с проверкой SHA-256 и предлагают
перезапуск. Если пользователь согласится, версия заменится после закрытия
клиента. Рядом с клиентским EXE должен лежать apply_update.ps1; папка
приложения должна разрешать запись. Обновляется только клиентский EXE,
сервер, батники и данные не обновляются. На Mac обновление EXE не
применяется. Клиенту нужен доступ к серверу по локальной сети и
разрешение Windows Firewall на порт 8765.

Через API доступны:
• Ozon: товары/маркировка, остатки, заказы FBO+FBS, поставки,
  финансовые операции и возвраты.
• Файл Ozon «Управление остатками»: вкладка «Итоги остатков по срезам»
  суммирует «Всего товаров», «Доступно к продаже», «Доставляем покупателям»
  и «Возвращаются от покупателей» по SKU. В деталях есть расчёт текущего
  количества в пути в обе стороны и доли доступного остатка. Это состояние
  на дату выгрузки, а не число доставленных или отказов за период.
• Если добавить вместе «Управление остатками» и «Юнит-экономика», таблица
  «Продажи и текущие остатки» соединит товары по SKU. Колонки «Период» и
  «Дата среза остатков» остаются разными. Из юнит-экономики берутся
  переданные в доставку, доставленные и возвращённые товары; разница
  «передано минус доставлено» не считается отказами, так как включает
  другие незавершённые исходы.
• «Передано за вычетом возвратов за период, шт» = «Передано в доставку
  покупателям, шт» − «Возвращено товаров, шт». Например, 181 − 11 = 170.
  Показатель виден по каждому SKU и в «Итогах по периодам». Это расчёт
  движения за период, а не фактический остаток на дату среза.
  В таблицах товара три столбца «Передано», «Возвращено», «Передано за
  вычетом возвратов» находятся сразу после артикула, SKU и названия.
  После обновления полностью закройте прежние окна клиента и сервера:
  запущенный старый процесс не подхватит новые столбцы из заменённого ZIP.
• WB: карточки/маркировка, текущие остатки, заказы, поставки FBS,
  финансовая детализация и воронка продаж.

ВНИМАНИЕ: API не заменяет все выгрузки кабинета один в один. Некоторые
отчёты требуют отдельной категории токена или подписки. Для неподдержанного
метода используйте прежнюю загрузку файла — она сохранена в приложении.

ЧТО ИСПРАВЛЕНО
• Таблица с сеткой ячеек, буквами столбцов и номерами строк в обоих разделах.
• Одна кнопка загрузки всех отчётов. Можно выбрать Ozon и WB вместе,

• Добавлены общие сводки и итоги, соединение одинаковых периодов,

ЗАПУСК И СБОРКА WINDOWS
1. Распакуйте архив полностью в отдельную папку.
2. Значок глаза уже включён: 1.ico для Windows и glazok.png для окон.
   Одинаковый значок ставится клиенту и серверу.
3. Установите Python 3.10+ для Windows с Tcl/Tk (подойдёт Python 3.12),
   при установке отметьте Add Python to PATH.
4. Запустите 1_BUILD_AND_RUN.bat (он вызывает BUILD_WINDOWS.bat).
   Для первой сборки нужен интернет для установки зависимостей.
5. Батник соберёт dist/Глазок.exe и dist/Глазок Сервер.exe, встроит
   иконку в оба файла и сразу запустит их.
6. В папке dist будет START_GLAZOK.bat. На серверном ПК он запускает
   сервер и приложение; на клиентском достаточно Глазок.exe и
   apply_update.ps1. Python для готовых EXE
   не требуется. Перед пересборкой закройте оба приложения.

Надпись «Сервер: доступен» означает только связь. Рядом указано, какие
ключи сохранены. Для отчётов нужны действующие ключи с правами API.
Кнопка «ⓘ Как пользоваться» в сервере объясняет поля и действия. На Mac
вставляйте ключ через ⌘V или кнопку «Вставить» возле поля.
Если порт 8765 занят другим «Глазок Сервер», приложение может работать
через первый экземпляр; его журнал находится в первом окне. Не запускайте
сервер повторно, если он уже открыт. На клиентском ПК настройте адрес
через «Подключение к серверу».

MAC
Windows EXE собирается на Windows. На Mac можно запускать исходники:
в терминале внутри папки выполните bash RUN_MAC.command. Откроются два
окна: «Глазок Сервер» и «Глазок»; второй терминал не нужен.
Если порт 8765 занят, просмотр на Mac выбирает другой свободный локальный
порт. Уже работающие программы не закрываются. Оба окна нового запуска
используют один и тот же порт.
Нужен Python 3 с Tkinter. Файлы BAT предназначены для Windows.
Для HTTPS-запросов используется системное доверие к сертификатам macOS.
Если сеть или VPN заменяет сертификат своим, этот сертификат должен быть
доверенным в macOS; проверка HTTPS не отключается.

ЗАГРУЗКА
Нажмите «Добавить файлы Ozon / WB» и выделите все нужные отчёты.
Поддерживаемые контейнеры: XLSX, XLSM, XLS, CSV, TSV, ZIP, включая
расширения заглавными буквами. Для XLS используется xlrd.
Контейнер XLS/CSV сам по себе не гарантирует знакомую структуру отчёта:
если заголовки неизвестны, содержимое показывается без расчётов.
ZIP читается без запуска содержимого, вложенные ZIP не раскрываются.
Временные файлы Excel (~$...) при добавлении папки пропускаются.

Проверенные типы Ozon: юнит-экономика, выкупы, CSV заказов, возвраты,
доступность, остатки (включая снятые с продажи), поставки, маркировка.
Проверенные типы WB: воронка, лента заказов, история остатков, поиск,
доходы и расходы по товарам, недельные финансы магазина, старый отчёт
поставщика с детализацией по складам/баркодам/размерам.

Файлы «21-8-2026 Д и Р...» и «21-8-2026 Аналитика остатков...» — WB,
даже если лежат в вашей папке OZ. Программа распределяет их автоматически.

Каждая загрузка добавляет файлы к предыдущим и пересчитывает результат.
Для нового набора или замены старого снимка нажмите «Очистить всё».
Замечания по файлам показываются сообщением и сохраняются в окне ⓘ Справка.
Повреждённый файл не мешает обработке остальных файлов.

ОБЩАЯ СВОДКА И РАСЧЁТЫ
Товарные отчёты объединяются по артикулу и точно совпадающему периоду;
для Ozon учитывается схема. Идентификаторы сохраняются как текст.
Данные дневных отчётов разбиваются по границам периодов, но месячные
суммы не распределяются искусственно по дням. В общей сводке указано,
какие строки относятся к полному периоду, а какие — к дневной детализации.
Если дневные данные покрывают тот же полный интервал, они присоединяются
к той же строке товара. Неоднозначные схемы FBO/FBS не размножают CSV.

Исходные колонки подписаны типом отчёта, новые — словом «Расчёт».
Разные источники похожих показателей остаются отдельными колонками.
Пустое значение — данных нет; ноль — известное нулевое значение.

Добавленные показатели при наличии исходных данных:
— заказы, продажи и выкупы в день;
— средняя сумма продажи, выкупа и перечисления за выкуп;
— доли доставок, отмен, возвратов и конверсии;
— незавершённые заказы и расхождения между источниками;
— сумма удержаний, удержания/продажи, итог/продажи;
— средний и начальный/конечный дневной остаток, изменение остатка,
  дни с нулевым остатком и количество наблюдавшихся дней;
— запас в днях, целевой запас и потребность на 28 дней, приоритет пополнения.

«Итоги по периодам» складывают аддитивные показатели отдельно по
периоду, типу блока, схеме и источнику. Проценты, цены, сроки и средние
не суммируются. Основные доли заново рассчитываются из итоговых сумм.
Итоги финансов WB отдельно группируются по периоду и валюте;
расходы всего магазина не приписываются отдельным товарам.
Не складывайте перекрывающиеся периоды разных отчётов между собой.

ВАЖНЫЕ ОПРЕДЕЛЕНИЯ
• Ozon «уровень выкупа за последние 50 заказов» — показатель из отчёта,
  не доля за календарный период. Разные значения не усредняются.
• «Без отмен и возвратов» = заказано − отменено − возвращено.
  Это не подтверждённые выкупы: часть заказов может быть не завершена.
• Заказы CSV идут по дате принятия в обработку; возвраты — по дате
  возврата. Нельзя делить эти возвраты на эти заказы для процента выкупа.
• Стоимость товаров CSV = предельная цена × количество; это оценка,
  не выплата и не прибыль. Валюты разделены.
• Прибыль юнит-экономики — показатель исходного отчёта. В oz3
  себестоимость нулевая, поэтому это не подтверждённая чистая прибыль.
• Остатки — срез на указанную дату. oz1 не имеет подтверждённой даты
  и остаётся отдельным блоком. Текущий остаток старых WB-отчётов тоже
  не выдаётся за остаток на конец исторического месяца.
• Остатки берутся из листа «Товары», а складские/кластерные детали
  сохраняются для проверки и не прибавляются повторно.
• Маркировка присоединяется к остаткам только того же SKU и даты среза.
• Оценка поставки на 28 дней = максимум(0, округление вверх(
  среднесуточные продажи × 28 − доступный остаток − поставки в пути)).
  Вариант без учёта пути показан отдельно. Срок поставки и сезонность
  неизвестны и не учтены. При нулевом темпе запас в днях не вычисляется.
• Для примера 10 шт. в день и 20 шт. в остатке: спрос на 30 дней —
  300 шт., довезти без учёта пути — 280 шт. Если в пути 50 шт.,
  довезти нужно 230 шт. Эти расчёты показываются лишь при наличии
  среднесуточных продаж и остатка в отчёте.
• В доступности из нескольких снимков одного периода для сводки
  используется последний датированный снимок; подробные версии сохранены.
• Дневные значения отчёта поставок не называются продажами. Итоги товара
  и строки поставок не складываются дважды.
• При конфликте версий исходные строки сохраняются; предупреждение
  объясняет, какая версия попала в расчёт. Очистите набор для замены.
• Если дата предыдущего периода не указана, соответствующие значения
  подписаны «даты не указаны» и исключены из итогов текущего периода.
